## 🚀 What's Ready for Day 1

### To Implement (5 Methods)
```python
class BM25Search:
    def _build_index(self) → None           # Build term → [docs] mapping
    def _tokenize(self, text) → List[str]   # Split & lowercase
    def _idf(self, term) → float            # Compute inverse document frequency
    def _score_document(self, doc_id, query_terms) → float  # BM25 score
    def retrieve(self, query, k) → List[Tuple]  # Top-k results
```

### To Test
- 30+ test cases covering:
  - ✅ Success paths (retrieve, score, rank)
  - ✅ Edge cases (empty query, k > docs, single doc)
  - ✅ Failure cases (no matches, unseen terms)
  - ✅ Case sensitivity and normalization
  - ✅ Error handling (ValueError for invalid inputs)

### To Learn
- Concept: **BM25 Scoring** (term frequency + inverse document frequency)
- Why it matters: Relevance ranking for enterprise search (Jira, ServiceNow, z/OS)
- Application: Build a foundation for vector search and RAG later

## 💡 Key Design Decisions

### Why This Approach?
1. **One day, one branch, one concept** → Manageable scope, clear focus
2. **Tests first, code second** → Specification-driven learning
3. **Synthetic data only** → Safety and reproducibility
4. **Memory system** → Adaptive teaching, no repetition
5. **Small commits** → Clear learning artifacts, easy to review
6. **Enterprise parallels** → Connect to z/OS, Jira, ServiceNow

### Why Day 1 is BM25?
- ✅ Foundation for understanding ranking and relevance
- ✅ No external dependencies (standard library only)
- ✅ Connects to enterprise search (Jira, z/OS logs)
- ✅ Springboard for vector search comparison later
- ✅ Manageable scope for 3–4 hours

### Why Tests Are Comprehensive?
- ✅ Tests *teach* (each test name explains what should work)
- ✅ Tests *specify* (exact expected behavior)
- ✅ Tests *validate* (all edge cases covered)
- ✅ Tests *guide* (implement in order of test class names)
